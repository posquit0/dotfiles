# HTML 슬라이드덱 표준 가이드

전달받은 내용을 **단일 HTML 파일** 슬라이드덱으로 만든다.
디자인·동작 표준은 `templates/deck.html`에 고정되어 있고, 덱마다 바뀌는 것은 **콘텐츠와 accent 색 한 쌍뿐**이다.

## 0. 절대 규칙

- 파일 하나로 완결. 외부 리소스는 **Google Fonts 링크(IBM Plex Sans KR · IBM Plex Mono) 하나만 허용** —
  템플릿에 이미 포함되어 있고, 오프라인이면 시스템 폰트로 자연 강등되므로 추가·변경하지 않는다.
  그 외 외부 CSS/JS/이미지 로드 금지
- 언어는 한국어 (`<html lang="ko">`), 폰트 스택은 템플릿 그대로 유지
- 템플릿의 구조 CSS·JS·하단 조작 인터페이스(chrome)는 수정하지 않는다.
  커스터마이징은 `:root`의 `--accent` / `--accent-soft` 교체만
- **하단 조작 인터페이스는 모든 덱에 항상 동일하게 포함**: 좌하단 원형 ←/→ 버튼(`.navbtns`),
  우하단 카운터 pill(`.counter`), 중앙 힌트(`.hint`), 상단 프로그레스 바(`.progress`)
- **인라인 style로 font-size를 줄이지 않는다** — 템플릿 타이포는 전사 공유 기준으로 조정된 최소값이다 (§2)
- 시크릿·고객 개인정보는 슬라이드에 넣지 않는다 (예시 값은 `●●●●●●` 또는 플레이스홀더)

## 1. 템플릿과 구성 방식

템플릿은 `templates/deck.html` 하나다. 컴포넌트가 설명형·밀도형을 모두 커버하므로,
**무엇을 만들지는 구성(어떤 슬라이드를 어떤 컴포넌트로 채우는가)으로 결정**한다.

| | 설명형 구성 | 밀도형 구성 |
|---|---|---|
| 목적 | 개념 교육, 아키텍처 설명, 팀 공유 발표 | 실행 가이드, 런북, 감사 대응, 비교 분석 |
| 중심 컴포넌트 | `.lede`+`mark` 비유, `.pipe` 다이어그램, 틴트 카드 | `pre.code` 2단, `table.cmp`, `ul.tick` 체크리스트 |
| 슬라이드당 | 한 아이디어 | 한 주제 묶음 (내부 스크롤 허용) |
| 분량 가이드 | 10~22장 | 제한 없음 (단계 수만큼) |

애매하면: 듣는 사람이 "이해"가 목적이면 설명형, "따라 하기/참조"가 목적이면 밀도형 구성.

## 2. 가독성 원칙 — 전사 공유 기준 📺

이 덱은 **큰 회의실 빔프로젝터·화상 공유 화면**에서 읽힌다고 가정한다.
"뒷자리에서 안 보여요"가 나오면 실패다.

- 템플릿 타이포 스케일이 기준: 본문 최소 17px, lede 최소 19px, 테이블 셀 최소 15px.
  **어떤 경우에도 인라인 style로 이보다 줄이지 않는다**
- 내용이 넘치면 **폰트 축소가 아니라 슬라이드 분할** — 정보를 빼는 것이 정답, 글씨를 줄이는 것은 오답
- 슬라이드당 시각 요소(카드 그룹·테이블·코드·다이어그램)는 **최대 2개** — 그 이상이면 분할
- 테이블 6행 이하, 카드 텍스트 2문장 이하, 코드 12줄 이하 권장
- 발표용 슬라이드는 한 화면에 들어가야 한다. 내부 세로 스크롤(`overflow-y:auto`)은
  밀도형(참조용 런북)의 긴 코드·체크리스트에만 허용
- 완성 후 셀프 체크: 브라우저를 절반 크기로 줄여도 본문이 읽히는가? (≈ 뒷자리 시야)

## 3. 테마 팔레트

밝은 종이(`--paper`) + 모눈 그리드 배경, 다크 네이비 코드 패널은 불변.
덱마다 `--accent` / `--accent-soft` **한 쌍만** 교체해 고유한 분위기를 준다.
의미색(green=긍정, red=부정, amber=주의)은 판정에 쓰이므로 절대 바꾸지 않는다.

| accent | `--accent` | `--accent-soft` |
|---|---|---|
| blue (기본) | `#2F63E0` | `#E3EBFB` |
| teal | `#0F8A7A` | `#DCF2EE` |
| violet | `#6D4FD0` | `#EAE4FA` |
| rose | `#C2417A` | `#FAE3ED` |

같은 시리즈(같은 프로젝트의 연속 덱)는 accent를 통일하고, 다른 주제는 다른 accent로 구분한다.

## 4. 콘텐츠 구성 원칙

덱의 서사 구조는 다음 순서를 따른다:

1. **표지** (`.slide.title`) — eyebrow(영문 대문자 주제 라벨) + h1(핵심 키워드는 `<span style="color:var(--accent)">`) + `.stamprow` 도장(선택) + `.lede`("무엇을" + "왜") + `.meta`(장수·조작법)
2. **아젠다** — PART별 카드(`.cols.c3` + `.tag` + `ul.dot`)로 전체 지도를 먼저
3. **문제/맥락** — 이 개념이 풀려는 문제를 먼저. 좋은 점 vs 문제점은 `tint-g`/`tint-r` 카드 대비로
4. **개념 각론** — 주제마다 슬라이드 1장: `<mark>` 강조가 든 h2 → `.lede` 정의(비유 포함) → 불릿 또는 다이어그램
5. **딥다이브** — 헷갈리는 지점은 "A vs B" `table.cmp`로 정면 돌파, 셀 판정은 `.good`/`.bad`/`.mid`
6. **우리 적용** — 반드시 실제 우리 코드/인프라와 연결, 전략·역할 분담은 `.cake` 레이어로
7. **한 장 요약** — `ul.dot` 복기 + `.stamprow` 결론 도장 + 참고 자료 카드

### 컴포넌트 사용 규칙

| 상황 | 컴포넌트 |
|---|---|
| 슬라이드 상단 라벨 | `.eyebrow`: `<span class="no">NN</span>PART N · 라벨` — 표지 제외 모든 장에 2자리 번호 |
| 제목 핵심어 강조 | h2 안 `<mark>` — 장당 1개 |
| 도입·정의·비유 | `.lede` — 일상 사물 비유를 문장에 녹인다 (별도 비유 박스 없음) |
| 순서·파이프라인 | `.pipe` (강조 노드는 `.hot`) |
| 그룹·나열 | `.card` + `.tag` (긍/부/주의/포인트는 `tint-g`/`tint-r`/`tint-a`/`tint-b`) |
| 체크·안티패턴 리스트 | `ul.tick` / `ul.tick.cross` / 중립은 `ul.dot` |
| 비교·선택 기준 | `table.cmp` (+`.tablewrap`) — 산문 금지, 판정은 `.good`/`.bad`/`.mid` |
| 계층·역할 분담 | `.cake` (`.l1`/`.l2`/`.l3`) |
| 판정·상태 도장 | `.stamp` `ok`/`deny`/`mut` (표지·요약은 `.big`) |
| 코드 | `pre.code` + `.c`(주석)/`.k`(키)/`.s`(문자열)/`.n`(숫자), 캡션은 `.codewrap`+`.cap`, 설명과 나란히 2단(`cols c2`) |
| 인라인 코드 / 키 입력 | `code.inline` / `.kbd` |
| 바닥 한 줄 정리 | `.footnote` — 슬라이드 맨 아래 실무 관점 코멘트 |

스타일 규칙:
- 슬라이드당 하나의 아이디어. 불릿은 3~5개를 넘기지 않는다
- 강조는 `<strong>` — 문장당 1~2개, 남발 금지
- 코드는 핵심 줄에만 주석, 옆 컬럼에 "읽는 법" `ul.dot`을 붙인다
- 톤: "중학생도 이해할 수 있게" — 전문용어 첫 등장 시 비유로 풀고, 이후 원어 사용

## 5. 인터랙티브 컴포넌트 🎬

정적 슬라이드보다 **직접 보여주는 편이 설명이 쉬운 내용**을 발견하면 아래 3종을 사용한다.
콘텐츠를 훑으며 "이건 순서대로 등장해야 산다", "이건 실행 장면을 봐야 안다", "이건 경우에 따라 다르다"
싶은 지점이 후보다. 장식이 아니라 설명 도구 — **덱당 2~4곳, 슬라이드당 1개**를 넘기지 않는다.

| 컴포넌트 | 쓰는 때 | 마크업 |
|---|---|---|
| `.frag` 순차 공개 | 파이프라인 단계, 레이어 쌓기, 문제→답처럼 **등장 순서가 설명의 일부**일 때 | 등장할 요소에 `class="frag"`. 한 박자에 함께 나올 요소들은 같은 `data-frag="N"` |
| `.term` 터미널 데모 | **CLI 워크플로우** — 명령을 치면 무엇이 나오는지 보여줘야 할 때 (정적 `pre.code`보다 우선 고려) | `.term > .term-head(+.term-play 버튼) + .term-body > .tl.cmd / .tl.out` — 클릭마다 cmd가 타이핑되고 out이 나타남 |
| `.tabs` 탭 전환 | 같은 주제의 **대안·시나리오·전/후**를 한 슬라이드에서 전환하며 비교할 때 | `.tabs > .tabbar(.tab-btn) + .tab-panel` — 첫 버튼/패널에 `on` |

동작 규칙 (템플릿 JS에 구현됨):
- `→`/Space는 현재 슬라이드의 미공개 `.frag`를 먼저 공개하고, 다 공개되면 슬라이드를 넘긴다.
  `←`는 마지막 조각을 되감고, 이전 슬라이드로는 조각이 모두 펼쳐진 상태로 진입한다
- `.term`은 아무 곳이나 클릭할 때마다 한 박자씩 재생 (cmd 타이핑 → 이어지는 out 일괄 표시),
  끝나면 `↺ 처음부터`로 리셋. `.tl.cmd`에는 자동으로 `$ ` 프롬프트가 붙는다
- 인쇄(PDF)에서는 frag·tabs·term 모두 **펼쳐진 상태**로 출력된다
- 주의: `.frag`는 발표 키 입력을 소비하므로, 빠르게 넘겨 보는 참조용(밀도형) 덱에는 쓰지 않는다

## 6. 동작 표준 (템플릿 JS에 이미 구현됨)

- 키보드: `←`/`→`/`Space`/`PageUp`/`PageDown` 이동(조각 우선), `Home`/`End` 처음/끝, `F` 전체화면, `P` 인쇄(PDF)
- 하단 chrome: 좌하단 원형 ←/→ 버튼, 우하단 `01 / 22` 형식 카운터 pill, 중앙 힌트(모바일에선 숨김), 상단 프로그레스 바
- 모바일: 좌우 스와이프로 이동
- 본문 클릭으로는 넘어가지 않음 (코드 드래그·`.term` 재생 클릭과 충돌하므로 의도적으로 없음)
- `@media print`로 슬라이드당 1페이지 PDF 내보내기 지원
- 마지막 슬라이드에서 순환하지 않음 (clamp)
- URL 해시 딥링크: 슬라이드 이동 시 URL이 `#N`으로 동기화됨 (`replaceState`라 뒤로가기 오염 없음).
  `파일주소#7`처럼 특정 슬라이드 링크를 공유하면 그 슬라이드에서 열림

## 7. 작성 후 검증

1. 열어서 확인: `open <파일>` (또는 playwright로 표지 스크린샷 — file: 프로토콜이 막혀 있으면 `python3 -m http.server`로 잠깐 서빙)
2. 체크: 표지에 `active` 클래스가 있는가 / eyebrow 번호가 실제 장 번호와 맞는가 / 표지 `.meta`의 장수가 맞는가 / 긴 table·pre가 가로로 넘치지 않는가 (발표용인데 세로 스크롤이 생기면 슬라이드 2장으로 분할 — 폰트 축소는 금지)
3. 인터랙티브를 넣었으면: `.frag`는 `→` 키로 공개 순서 확인, `.term`은 클릭으로 끝까지 재생 확인, `.tabs`는 전환 확인
4. 산출물 위치: 관련 프로젝트의 `docs/` 옆 (예: `apps/<앱>/docs/<주제>-slides.html`), 프로젝트가 없으면 사용자에게 위치 확인
5. 사내 공유가 필요하면 `publish-html` MCP로 게시 (VPN 내부 링크) — 사용자가 요청할 때만
